# Kitlane account service

Development project: `floral-darkness-58175880`, AWS Frankfurt. Production branch: `br-muddy-art-ba6qrst6` (untouched schema/Auth). Development branch: `br-damp-cell-batye88a`. Managed Better Auth uses shared Google OAuth credentials for development. Google credentials never ship in the desktop.

Run `npm ci`, `npm test`, `npm run typecheck`, `npm run build`. Runtime: Neon Functions Node 24. Packages are pinned in package-lock.json. `neon.ts` declares Function slug `kitlane` (no hyphens). Database connections come from injected `DATABASE_URL` using a small persistent `pg` pool.

Apply `migrations/001_accounts.sql` then `002_installation_proof.sql` on development only. Existing registrations lacking installation proof fail closed. `test/schema.sql` verifies composite account/device constraints, self/duplicate pair rejection, and snapshot isolation. Its temporary fixtures roll back. Never run test fixtures on production.

Server configuration is in `.env.example`. Put real values in ignored `.env.local`. `KITLANE_ORIGIN` is the exact HTTPS bridge/API origin, without a path. `KITLANE_AUTH_ISSUER` and `KITLANE_AUTH_AUDIENCE` must match the branch's issued Google-session JWT claims; checking cannot be disabled. Live verification confirmed that both are this branch's Auth origin, without `/kitlane/auth`. The anonymous-token endpoint uses a different issuer and cannot stand in for Google-session verification. Anonymous tokens cannot pass UUID and Google-account verification.

The bridge uses the official `@neondatabase/auth` wrapper, including Neon's OAuth verifier handling. The API additionally queries `neon_auth.user` and `neon_auth.account`: a verified, unbanned Google account is required and password/other-provider accounts are rejected. Do not configure additional OAuth providers or enable email/password for production; disable email/password in Neon Console. The connector currently exposes no field for changing that setting.

The pinned SDK injects the signed `set-auth-jwt` response header into `getSession().data.session.token`. The bridge reads this authenticated session JWT and rejects opaque/malformed token strings. In SDK 0.6.0-beta, `/token` shares the session cache and can return a session-shaped object after `getSession()`; a regression test uses the actual SDK to cover that behavior. Server signature, issuer, audience, age, expiry, subject and Google-only checks still authorize every handoff.

Official contracts checked: [OAuth setup](https://neon.com/docs/auth/guides/setup-oauth), [Auth SDK](https://github.com/neondatabase/neon-js/tree/main/packages/auth), [Function authentication](https://neon.com/docs/compute/functions/authentication). Shared Google credentials are for development; production needs your own Web application OAuth client with callback `{NEON_AUTH_BASE_URL}/callback/google` and the bridge origin registered as a Neon trusted domain.

`npm run build` bundles the official browser SDK and embeds the bridge into a standalone Node Function at `dist/index.mjs`; `neon.ts` deploys that artifact. Raw source startup refuses missing browser assets. Development is deployed at `https://br-damp-cell-batye88a-kitlane.compute.c-8.eu-central-1.aws.neon.tech`, registered as a trusted Neon Auth origin. Production remains untouched.

The bridge is served at `/sign-in` and `/` because Managed OAuth can return to the trusted origin root. This tab retains the pending attempt identifier in session storage for at most five minutes; the SDK handles the OAuth verifier. The identifier cannot authorize a computer without a Google session and the native PKCE verifier. Attempt storage is cleared before returning to the desktop. Real Google-session verification is tracked in `app/docs/development-deployment.md`.

For an opt-in hosted callback/vault/refresh/sign-out check, run `cargo run --locked -p kitlane-account-client --example live-check` from `app`. Authorize the explicitly named development check in the browser. It uses a unique diagnostic device, removes its local vault entries afterward, and never scans or uploads inventory. It does not sign the main GUI out.

Sign-in attempts use a quota keyed by the unguessable installation proof. Exchange/refresh quotas bind to an existing handoff/session credential rather than a shared public allowance; junk requests cannot spend other users' quotas or create arbitrary refresh quota rows. Expired attempt/quota cleanup is bounded. This is application abuse control; Neon Functions does not document a trustworthy caller-IP header or a customer-configurable ingress WAF. Production edge protection must be configured separately rather than trusting client-supplied forwarding headers.

Transactional integration tests use the isolated `account-tests` branch `br-falling-sun-barbvxtf` only: `node --env-file=.env.test.local --import tsx --test test/database.test.ts`. The ignored file contains its database URL and `KITLANE_TEST_BRANCH`; the test checks both branch ID and endpoint hostname before creating fixtures. Fixtures use random UUIDs and `.invalid` email addresses and are removed in `finally`. This test exercises real concurrent code/handoff/refresh consumption, expiry, self/foreign pairing, snapshot authorization, PKCE/device substitution, and revocation. Ordinary `npm test` skips this one test when no test database is configured.
