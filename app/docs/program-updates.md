# Installed program updates

Windows x64 users choose individual applications in Settings → Automatic updates. Update now is also available in Library app details. Policies are local to this computer and default off. A separate installed agent checks approximately every six hours with bounded jitter, continues after the window closes, and starts at user login while any automatic policy is enabled.

Every operation uses an exact catalog WinGet ID and a fresh inventory observation. The provider must identify exactly the selected installation with a known numeric version and scope. Microsoft App Installer is resolved from its protected WindowsApps package, using package registration when directory listing is denied; no PATH executable, alias, shell or PowerShell command is accepted. Protected paths reject reparse points. This relies on Windows protecting Program Files, its Microsoft package directory, and HKLM registration; it is not an independent Authenticode verification implementation.

The named WinGet source must export the expected Microsoft URL, source type and identity. Discovery and execution use discrete fixed arguments, an exact target version and scope, silent noninteractive mode, and no dependency installation. The provider respects security checks and never uses blanket upgrade, force, unknown-version or pinned overrides, automatic agreement acceptance, or reboot flags. Discovery output/time are bounded. Live installers are polled rather than killed on a timeout.

WinGet pin output has no structured format in the supported CLI contract. This implementation requires positive English evidence that no pins are configured. Any pin, localization or ambiguous output requires manual review; it deliberately does not guess which pin is safe to bypass. Non-numeric versions, ambiguous installations, partial inventory failures, source changes, new agreements, elevation and restart outcomes also require attention.

Jobs record intent and exact old/target versions before execution. Source and installed state are checked again immediately before launch. Success requires independently observed canonical product, publisher, scope and expected newer version; an exit code alone is insufficient. MSI registration keys and versioned display names can change, so verified updates rebind the opted-in policy to the new observation. Interrupted installers become indeterminate and cannot replay until explicitly reviewed in Settings. No third-party program was updated during development.

Validation: pure request/source/argument/version/identity fixtures, bounded subprocess-output fixtures, policy/durable-ledger tests, MSI registration migration tests, and an opt-in read-only native Microsoft provider/source test. Real vendor installers and elevation/restart flows still require disposable-machine integration testing.
