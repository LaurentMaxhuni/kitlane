# macOS inventory coverage

Phase 2 reads `.app` directories under `/Applications`, `/System/Applications`, and the current user's `~/Applications`. Machine/system roots use machine scope; the home root uses user scope. Up to two nested directory levels are traversed, including utility folders. Application contents are never traversed for embedded applications. Hidden directories and `.framework`, `.bundle`, and `.plugin` packages are excluded. Sources, parent components, entries, `Contents`, and `Info.plist` are inspected for links; linked entries are skipped. The fixture scanner also rejects Windows reparse points.

Only `Contents/Info.plist` is read, using the plist crate's XML/binary parser. No executable, subprocess, signing tool, elevation, network request, write, installer, or updater runs during scanning. Bundle metadata is observation: directory presence does not prove the application works, and bundle IDs do not verify publisher, signatures, catalog identity, or update availability. Publisher and origin remain unknown (`None`). Localized `InfoPlist.strings`, other users, apps outside these locations, legacy bundles, command-line tools, and linked apps are outside coverage. Every successful snapshot carries a coverage warning.

Names prefer `CFBundleDisplayName`, then `CFBundleName`, then the `.app` directory stem. Version prefers `CFBundleShortVersionString`, then `CFBundleVersion`; absent values stay unknown. `CFBundleIdentifier` becomes optional `native_id`. Empty strings become absent; observed fields reject controls and oversized values. Missing/unreadable, malformed, linked, wrongly typed, or oversized property lists warn and skip their bundle. A valid dictionary with unknown identity fields can still produce an observed directory-name record with an explicit missing-identifier warning. No publisher is inferred from the identifier or copyright text.

Limits: 40,000 visited directory entries, 10,000 retained apps, 256 KiB per plist, 1,024 aggregate dictionary keys, 4,096 aggregate values, 16 plist nesting levels, 256 bytes per key, 16 KiB per plist string, and 1 MiB of cumulative decoded string/key/data bytes. Each repeated binary reference counts again toward the decoded-byte budget. A custom serde visitor enforces structural limits before a bounded value tree is read to verify original field types; repeated binary references count against both the value and decoded-byte budgets. Output names allow 512 bytes, versions 128 bytes, and bundle IDs 256 bytes. Warning count is capped at 64 with a suppression marker. Exceeding traversal/app limits returns `LimitExceeded`; exceeding per-bundle metadata limits skips that bundle with a warning. Directory nesting beyond coverage warns.

Absent, unreadable, linked, and non-directory sources produce path-free warnings when another source is readable. If no source can be read, scanning returns `SourceUnavailable`, including when every configured source is absent. A readable empty directory can produce an empty inventory. Invalid device metadata, clock, or output records return explicit errors. Non-macOS native scanning returns `UnsupportedPlatform`; fixture scanning remains available to unit tests on Windows.

Deduplication uses canonical bundle path and install scope, retaining separate copies even when they share a bundle identifier. IDs are opaque UUID v5 values derived from scope and canonical path. IDs survive display/version changes; moving a bundle changes its ID. Canonical paths, home paths, filenames used for diagnostics, and OS error text are not emitted in warnings or synced fields. The directory stem can appear as the observed app name when name metadata is absent. Enumeration order does not affect final ordering.

This pass is an observational filesystem scan, not an atomic snapshot. Standard-library link/type inspection occurs before opening/enumerating paths; another process can replace a path between those operations. macOS plist opens use `O_NONBLOCK | O_NOFOLLOW`, then inspect the descriptor for a regular file, preventing a replaced FIFO from blocking the scan and rejecting a final-component symlink. Directory/ancestor replacement races remain possible. Reads are capped even if a plist grows. No race-free filesystem confinement is claimed.

Windows fixture tests exercise XML/binary metadata, unknown metadata, malformed/oversized/invalid fields, key/value/depth limits, bounded traversal, duplicate paths, separate scopes, stable IDs, source failures, and warning limits. Unix-only fixtures check linked bundle directories, nested directories, property lists, contents directories, and source roots. The scanner and Unix fixtures also compile cleanly for `aarch64-apple-darwin`; this is compilation evidence only. Native macOS scanning, no-follow/nonblocking descriptor behavior, and Unix link fixtures require runtime validation on a Mac; Windows test success does not establish macOS runtime behavior.

```text
cargo test --manifest-path app/Cargo.toml -p kitlane-core inventory_macos
cargo test --manifest-path app/Cargo.toml -p kitlane-core reads_standard_macos_sources_without_launching_applications -- --ignored --nocapture
```
